## 3. 最高优先级问题

### P0-01：什么算“2,000 道独立试题”

需要区分大题/小问、共用材料的题组、截图题、重印题和不同来源的同一道题。推荐使用**规范化逻辑题目 ID** 计数，子问另计但不重复增加顶层题量；可独立使用的阅读题目由内容结构定义。**该计数原则已于 2026-11-10 批准（DEC-039）**。见 `OID-001` 的关闭记录。

### P0-02：授权与内容审核的可执行性

2026-11-09 的规划文档不代表拥有原题重分发许可，也不代表已有 2,000 道正确答案。应建立授权证据登记和答案审核记录；规模目标能否如期满足取决于合法可用素材与审核投入。审核证据已依据 DEC-040 明确；实际授权及制作仍待推进，见 `OID-004`。

### P0-03：公共题库更新与个人修改如何共存

建议公共资源不可直接覆写个人内容；用户修改形成独立覆盖层/副本。正式展示优先级、冲突提示和组卷引用版本应明确，否则资源更新可能改变用户已保存的试卷。默认展示和固定组卷引用规则已依据 DEC-041 批准，见 `OID-003` 关闭记录。

### P0-04：功能测试版与正式 V1.0 的关系

**建议的澄清**：软件功能通过测试可形成内部/公开功能测试版，但**正式 V1.0** 需要软件功能、跨平台测试及 300/2,000/100 的内容验收全部通过。该解释与第 15、16、32、33 轮选择相容；仍应写进发布制度。见 `OID-005`。

## 4. 其他发现

1. **4GB / Win10 / Intel Mac 为兼容目标，不应被写成已验证承诺。** macOS 最低版本、处理器构建目标及旧系统支持由 PoC/测试结果确定。
2. **PDF 与 DOCX 的定位机制不同。** PDF 可存页码和归一化区域坐标；DOCX 重新排版可能改变页码，不能承诺稳定定位。
3. **截图型试题支持收藏和组卷，不等于可全文搜索。** 未执行 OCR 的图片只能靠显式录入元数据及附加文本检索。
4. **非商业不等于无版权风险。** 资料公开可下载不自动等于可嵌入软件重新发布；须逐资源留存授权或可靠权利依据。
5. **多小问可能存在依赖。** 单独组卷应检测依赖标识，并提供提醒或保留上级材料。
6. **SQLite 事务不覆盖外部文件。** 导入必须对附件分阶段处理、文件校验、原子元数据提交及崩溃恢复。
7. **同一题的不同原卷出现记录需要与题目实体分开。** 可避免重复题量和来源丢失。
8. **固定浅色 UI 与阅读字号调整不是同一要求。** 不新增复杂主题定制，保留基础页面缩放、系统字号适配与键盘可访问性。
9. **自动构建 ≠ Mac 实机可用。** Mac 的文件权限、字体、PDF 预览/打印、签名与公证均须在发布流程验证。
10. **严格内容验收会成为资源建设瓶颈。** 软件工程与题库编辑/许可审核宜独立推进，共用版本化数据规范。
