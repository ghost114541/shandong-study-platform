# PACK — 离线资源包格式与安全更新规范（草案）

**既定要求**：无账号/无服务器依赖、标准化资源包、版本与兼容性检查、完整性校验、重复处理、用户数据保护、失败后恢复一致状态。

## 1. 包容器与版本

建议后缀 `.studyzip`，底层为 ZIP 容器；**扩展名与内部结构尚未正式冻结**。用户可从本地选择文件导入。V1.0 不必强制实现在线资源中心、自动增量下载和数字签名信任链；这些属于此前未选的高级包管理能力。

```text
example.studyzip
├── manifest.json
├── data/
│   ├── knowledge.jsonl
│   ├── questions.jsonl
│   └── papers.jsonl
├── attachments/
│   └── <sha256>.<ext>
└── LICENSES/
    └── rights-and-attribution.json
```

### manifest 示例（说明性，不是最终协议）

```json
{
  "format": "shandong-study-resource-pack",
  "schema_version": 1,
  "pack_id": "demo.shandong.math.2026",
  "version": "1.0.0",
  "display_name": "示例：山东数学资源包",
  "min_app_version": "0.1.0",
  "content": {"knowledge": 2, "questions": 5, "papers": 1},
  "files": [{"path": "data/questions.jsonl", "sha256": "<64-digit-hex-hash>", "bytes": 1234}],
  "license_manifest": "LICENSES/rights-and-attribution.json"
}
```

`<64-digit-hex-hash>` 是非真实占位符。最终包规范应对所有文件声明大小、哈希、角色和 schema 版本，并定义清晰的拒绝规则。

## 2. 兼容性与质量

导入前检查：包格式、目标软件最低版本、数据库 schema 兼容、包唯一 ID 与版本、文件清单完整性、重复资源 ID、知识点引用是否存在、结构化内容是否符合 JSON Schema、来源权利记录是否足以支持**公开发布**。个人导入与正式分发的许可校验强度可以不同，但个人文件不可自动混入公共资源包。

区分：

- **文件哈希完整性**：证明字节与清单一致，不证明内容正确，也不证明可信来源。
- **签名与发布者身份**：高级方案，V1 暂不承诺完整可信签名生态。
- **内容审核**：题干/答案/解析的质量证据，不能由文件哈希替代。
- **版权授权**：法律分发依据，必须逐资源记录。

## 3. 安装状态机建议

```text
selected → inspected → staged → validated → committing → installed
                                       └──failed/recovering
```

1. 只读取 ZIP 元信息与受限清单，预估总文件数/解压体积，拒绝文件路径穿越、绝对路径、软链接逃逸、超高压缩比等异常。
2. 将附件写入私有暂存目录，逐个验证哈希与文件类型；不覆盖正式用户文件。
3. 用数据库事务建立待安装记录、资源版本和引用；采用幂等安装作业号。
4. 文件切换与数据库提交之间不具备天然分布式原子性；需要**可恢复安装日志**，在崩溃后明确继续完成或回滚。
5. 成功后记录包 ID/version、变更摘要；失败时保证已存在题库仍可正常打开。

### 冲突类型

| 情况 | 建议处理 |
|---|---|
| 同包同版本重复导入 | 提示已安装，不重复写入 |
| 同包更高版本 | 比较变更清单，校验兼容后升级 |
| 同题不同来源 | 用逻辑题与 `occurrence` 关联；不盲目合并 |
| 同一题公共版更新而存在用户版 | **保留个人覆盖且默认显示个人版本；允许切回公共原版；已保存组卷继续引用固定版本/快照（DEC-041）** |
| 引用不存在的知识点/文件 | 阻止安装或标识不完整，按发布包等级定义 |
| 低版本试图覆盖高版本 | 拒绝或走专门的已审查回退流程 |

## 4. 回滚、备份与恢复的差别

- **失败恢复**：针对某次安装，恢复数据库+附件的一致性。
- **用户备份**：整个个人资源库的完整快照，包括题目、收藏、附件、保存的组卷方案及必要配置。
- **资源包旧版安装/卸载**：更复杂的版本管理行为，是否属于 V1 尚待确认，不因选了“失败恢复”而自动承诺完整历史版本切换。

## 5. 资源清单质量字段

正式发布包中的资源项至少需包含：稳定 ID、学科、必要地区/年份/类型、原始来源、再分发权利依据、题干/答案/解析有无、核对状态与核对证据指针。无授权资料只应保留可合法记录的索引/来源信息，**不得擅自内置其受保护文件或全文**。

## 6. 发布包验收示例

- 正常包导入后数量与关联一致；重复导入数据量不增加。
- 损坏附件哈希与恶意路径包拒绝且不写入库外目录。
- 安装中强制退出后重启，能够识别未完事务并恢复一致状态。
- 更新公共答案后用户修改内容、收藏与保存的组卷仍可用。
- Windows 生成/导入的包可在 macOS 正确导入（反之亦然）。
