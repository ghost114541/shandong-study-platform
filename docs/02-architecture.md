# ARCH — 初步系统架构与技术边界

**状态：技术设计草案，不等于已完成 PoC。** 已决定：Tauri 2、React、TypeScript、Rust、SQLite；其他库与细节需技术验证。

## 1. 分层与职责

```text
┌───────────────────────────────────────────────────────┐
│ React + TypeScript                                    │
│ 首页/知识库/题库/卷库/预览/富文本编辑/组卷/资源管理  │
│ 仅负责交互、显示、表单校验与受限本地缓存             │
└─────────────────────┬─────────────────────────────────┘
                      │ Tauri 命令 (最小权限 IPC)
┌─────────────────────▼─────────────────────────────────┐
│ Rust 应用服务                                         │
│ Question / Knowledge / Paper / Search / Compose       │
│ FileImport / Package / Backup / Trash / Audit         │
│ 跨实体规则、校验、事务、权限控制、错误处理            │
└─────────────────────┬─────────────────────────────────┘
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
  SQLite + FTS/索引        本地文件资源存储
  元数据、版本与关系      原始 PDF/图片/附件/包缓存
```

### 建议的边界

- UI 不直接拼接本地任意文件路径或执行任意 SQL；通过经过校验的 Rust command/use case 访问。
- 核心业务规则不依赖 React 组件，便于单元测试和未来迁移。
- 所有第三方富文本输入由受控 schema 和白名单净化，禁止不受限的 HTML/脚本执行。
- 本地资源访问严格使用目录白名单、逻辑资源 ID 和解析后的安全路径；在 Tauri 能力授权中遵守最小权限。
- SQLite 数据迁移随软件版本管理；未成功迁移不得继续写入旧数据库。

## 3. 富文本与预览引擎候选（待 PoC）

- **结构化内容**：版本化 JSON 文档，包括段落、标题、行内公式、块级公式、表格、图片引用及受控题目节点。
- **编辑器**：评估 Tiptap/ProseMirror 等富文本模型，但未锁定具体编辑器依赖及版本。
- **公式**：评估 KaTeX/MathJax 的数学覆盖、错误提示、PDF 输出一致性；化学符号与结构式需专门试题样本。
- **PDF 预览**：评估 PDF.js 作为可搜索文本 PDF 阅读器；扫描版只显示页面，不自动承诺 OCR。
- **PDF 导出**：至少验证结构化题目→打印布局→独立试题/答案 PDF，重点核对跨页材料、长解答题、公式/字体嵌入、图片缩放和跨平台结果。
- **DOCX**：原件可存储；直接富文本转换不保证无损。可提供外部打开或可靠转换路径，需标示功能边界。

## 4. SQLite 与文件存储原则

- 结构化信息存 SQLite，文件以内容 ID/逻辑路径存独立资源目录。大型 PDF 不作为 SQLite 大 BLOB 批量存储。
- 使用外键约束、写事务、迁移版本和内容一致性检查。可评估 SQLite FTS5 与 B-tree 过滤索引。
- 文件库可按 sha256 内容地址存储，避免相同字节文件重复占空间；**不同文件并不直接意味着同一道题**。
- 内置资源与用户自建数据为不同命名空间/所有权；所有公共内容带包/版本来源；收藏及组卷通过稳定 ID 引用。
- 不把 `C:\\...` 或 `/Users/...` 这类绝对路径写成跨平台资源引用。用户选择存储根目录，DB 仅存相对 ID，迁移后重定位。

## 5. 安全与异常处理

- **资源包**：拒绝绝对路径、`../`、目录穿越、软链接逃逸、异常压缩比、超额总解压尺寸或未声明的内容；校验哈希与 schema。
- **完整性**：分阶段写入暂存文件 → 验证 → 事务性注册 DB → 文件切换与安装日志；异常后扫描事务记录并修复或恢复，不能声称普通 DB 事务可原子更新所有外部文件。
- **备份**：数据库一致性快照 + 附件清单及校验信息；恢复前备份旧状态，检查结构版本与缺失附件。
- **删除**：默认逻辑删除/回收站；公共基础包使用隐藏/版本规则，不允许用户误删基础数据。
- **诊断**：本地日志只保留必要技术错误，路径/文件内容脱敏，默认不上传。

## 6. 跨平台策略

- Windows **原生**开发与调试；WSL2 可用于辅助数据脚本，但不作为 Windows 版主要编译环境。
- Git 仓库+Windows/macOS 构建任务；Mac x86_64/arm64 构建策略及代码签名、公证流程按发布阶段核实。
- 真正验收包含 Mac 实机启动、资源访问、编辑器输入、文件对话框、PDF 预览与打印；CI 构建通过不等于实机兼容。
- 兼容旧版 Windows/macOS 与 4GB 电脑是努力目标，需要样机实测和明确最低版本边界。

## 7. 首批技术验证与退出条件

| PoC | 输入/场景 | 必须观察到 |
|---|---|---|
| POC-001 | 数学 LaTeX、复杂表格、物理图、化学式、语文长阅读、共用材料/小问 | 编辑/保存/重新打开无丢失；导出 PDF 内容正确；两平台布局问题被记录 |
| POC-002 | 逻辑题与小问/出现记录关系、九科元数据、10 万条合成题 | 关联/去重逻辑正确；搜索分页性能可测，内存可观测 |
| POC-003 | 正常/中断/损坏资源包、恶意解压路径、同题用户覆盖、备份恢复 | 不执行危险路径写入；失败后无半安装状态；用户数据保留 |

**通过 PoC 不是发布许可**，PoC 可保留不完整 UI/资源。若失败，先变更技术设计而非擅自删除用户需求，记录 DEC 及测试证据。
